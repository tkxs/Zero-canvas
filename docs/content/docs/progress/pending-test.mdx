# Pending Tests

The current release needs manual verification in these areas:

- USA0 authentication modal presentation: verify that signed-out, restoring, authorizing, syncing, needs-Key, ready, and error states have distinct and accurate feedback without changing the OAuth flow. The account summary, group-scoped Key creation, long Key names, group tags, per-Key errors and usage, destructive confirmation, footer actions, and long Key lists must remain readable and operable in English and Chinese, light and dark themes, and narrow mobile viewports. The body should scroll within the viewport, mobile Key actions must not overlap content, and no OAuth token or complete Key may appear in the DOM.
- USA0 account dashboard and Key management: clicking the avatar should open the compact dashboard, where usage inspection applies only to the displayed Key and never controls model routing. Account Management must replace local summaries from the complete website snapshot, because the website is authoritative for accounts, groups, and explicit Key create/delete operations. An account with no usable Key must remain in the needs-Key state while Account Management opens automatically; the user must still select a website group and confirm creation, and the app must never auto-select or auto-create. For a create whose response is lost or times out, retry the identical body with the same `Idempotency-Key` and create exactly one website Key. After a confirmed delete, remove that source immediately; if the following resync fails, do not restore it or create a replacement. Group synchronization must accept both the test service's array response and the contract's paginated response. A `success:false` envelope, missing `groups:read`, or malformed pagination must produce a clear service/contract error instead of `result.items is not iterable`. The test service must also register `groups:read` and `keys:write` for `zero-canvas-web`; creation must call `POST /api/v1/app/groups/:groupId/keys` with a body containing only `name`, while deletion must call `DELETE /api/v1/app/keys/:id`; log out and reauthorize after changing scopes. Verify usable, disabled, expired, ungrouped, quota-exhausted, empty-model, partial-failure, no-Key, no-group, long-list, narrow-screen, bilingual, light/dark, logout, and failed create/delete/resync states.
- USA0 multi-Key model routing: every usable website Key should independently request `/v1/models` and expose its models as `model name (Key name)` options; custom channels and custom invocation scripts are removed. Duplicate model labels from different Keys must remain separate and use the exact selected source. Verify two accounts that contain the same numeric Key ID cannot share credentials, cached models, defaults, usage, or in-flight results; refresh, account switch, cross-tab changes, focus resync, Key deletion, empty catalogs, and individual Key failures must atomically repair sources without falling back to another Key. Unknown or unsupported providers must fail closed instead of selecting a default transport.
- USA零画布 product name: verify the homepage hero, top navigation, browser title and description, canvas library title, new canvas names, and default export filenames display “USA零画布” in both languages, while USA零 website and account labels remain unchanged.
- Homepage background: verify the code rows drift smoothly in alternating directions over the grid, remain low contrast behind the hero content, follow light and dark themes, stop moving when reduced motion is enabled, and do not block buttons, prompt previews, scrolling, or image preview interactions on desktop and mobile.
- Codex plugin offline installation: download the plugin ZIP from the Connect local Agent page in local Vite, Docker, and the production static deployment. Its filename should include the plugin version, and the archive must preserve `.agents/plugins/marketplace.json`, the complete `plugins/infinite-canvas` folder, `install.ps1`, `install.sh`, and the root instructions. Verify the installer, manual commands, repeat updates, missing-Codex and installation failure messages on Windows and macOS/Linux. A new Codex task should load both canvas Skills and the Canvas Agent MCP without changing other plugins or marketplaces. Check light, dark, narrow-panel, bilingual, platform-default, command-copy, and download-failure behavior.
- Canvas media recovery: when opening an older canvas with missing, damaged, or unreadable local images, videos, audio, or conversation attachments, the page should enter the canvas after at most a few seconds instead of remaining on the skeleton indefinitely. Readable nodes and media should still appear, failed media should fall back to saved content, and canvas data must not be cleared or overwritten.
- USA0 authentication gate and website session reuse: `/` and `/oauth/callback` remain public, while protected routes must wait for hydration and resume the exact safe internal path after login and Key readiness. Source development and `docker-compose.local.yml` must default to `http://localhost:8080`; authorization must navigate only to `http://localhost:8080/oauth/authorize?request_id=...`, model synchronization must request only `http://localhost:8080/v1/models`, and production builds must still default to `https://usa0.top`. Before login, `POST /api/v1/app-auth/authorize/requests` must be sent without Cookie/Bearer and with credentials omitted; it must validate the exact registered Origin/client/redirect tuple, bounded fields, and S256 only, then return an opaque short-lived single-use `request_id`. The popup must navigate only to top-level `/oauth/authorize?request_id=...`, where the service's same-origin `HttpOnly` Cookie is the only website session and the request is revalidated. Verify that the local service exactly registers the `http://localhost:3000` CORS origin and `http://localhost:3000/oauth/callback` redirect, along with exact registered HTTPS deployment callbacks and explicitly registered loopback HTTP callbacks; reject wildcard, preview, suffix, unregistered port, and `null` origins. Also verify registration/login, consent rejection, replay, forged or concurrent state, popup closure, timeout, rate limiting, no sensitive authorization logs, callback isolation, exact CORS with `withCredentials` false and `Idempotency-Key`, and pending-route continuation.
- USA0 credential, session, and long-task isolation: full website Keys must be runtime-only and absent from every persistence, export/WebDAV, record/metadata, DOM/URL, clipboard/download, Cache/Service Worker, log/error/analytics, screenshot, callback, `postMessage`/BroadcastChannel, plugin storage, and plugin SDK/runtime sink; plugin APIs must expose no full-Key getter, enumeration, payload, or serialized config. Exercise concurrent login completion, refresh, logout, and account switching across tabs, including the localStorage lease fallback when Web Locks is unavailable; stale work must never reactivate the prior account. Start video tasks from two accounts/Keys, reload while pending, then switch account or replace a Key with the same ID: polling must require the recorded account ID, `channelId::modelName`, and Key fingerprint, or fail unavailable. Server errors that echo access, refresh, or full-Key credentials must be redacted before UI, logs, and diagnostics. Verify text, image, audio, video, Agent, and plugin calls resolve only the exact selected source.
- USA零 branding and official links: the web app, documentation site, README, Canvas Agent, and Codex plugin should use the new name and logo; the official website should open `https://usa0.top`, the top action area should not show a GitHub repository link or icon, and the QQ action should copy `1084450051`. Old website, group, email, sponsor, repository-ranking, popularity-chart, and community-promotion links should be absent. The release modal should read `VERSION` and `CHANGELOG.md` from the current repository and fall back to build-time local data when unavailable, while internal `infinite-canvas` storage, export, MCP, plugin SDK, and `@basketikun/canvas-agent` compatibility remain intact.
- Codex plugin local opening: after the USA零 Web frontend is running on port 3000 and the local Canvas Agent provides its URL and token, `open-canvas` should open `http://localhost:3000/canvas` with the connection parameters and must not fall back to the online website.
- Canvas Agent bundled Codex startup on Windows: when an npx cache contains the Codex platform binary but its aliased package metadata is missing, creating or resetting a conversation should still start the native `codex.exe`, complete MCP initialization, and keep the web connection alive.
- Canvas navigation: the bottom toolbar should switch between Select and Move modes and reflect the active mode with its icon; Select should draw a clearly spaced dashed range whose dash length, gap, and stroke width remain visually constant at every zoom level, while Move should pan from either the background or a node. Clicking blank canvas space in either mode should deselect the current node and close its top toolbar and lower prompt panel. Holding Control or Space should temporarily invert the active tool without changing the toolbar mode: Select becomes Move, and Move becomes range selection. After clicking any canvas-page button, pressing Space should only invert the tool and must not trigger that button again. Middle-button panning and additive node selection with Shift/Cmd should continue to work, while Space remains available inside text inputs and editable content.
- English and Simplified Chinese switching across navigation, settings, titles, descriptions, Ant Design components, and persisted preferences.
- Global Dropdown, Menu, Select, Cascader, and TreeSelect popup backgrounds, hover states, and selected states in both light and dark themes.
- Canvas node resize stability, prompt scrolling, generated-prompt restoration, edit-prompt persistence after closing an existing image or text node panel, expanded prompt editing with live synchronization and `@` references, image editing, drag-and-drop references, and generation configuration.
- Canvas side panel: clicking an element row should smoothly center and select its node without zooming above 100%; image elements with content should still open the large preview without triggering canvas focus.
- Multi-image canvas generation: starting N images should immediately create one image node with N expandable slots and one incoming connection; each empty slot should independently show generating or failure while requests are running, every slot with image content should always display that image, and the first successful image should appear as the primary image immediately. The collapsed state should use a compact stack with at most three closely spaced backplates and a clearly legible count control; clicking the control should hide the floating toolbar and expand the slots upward and to the right. Every completed secondary image should keep a clearly legible primary-image action visible in both themes, and clicking the empty canvas should collapse the group.

- Failed multi-image slots: every failed slot, including the current primary slot, should expose retry and delete actions. Retry should update only that slot without replacing an existing successful primary image; delete should remove only that failed slot and update the displayed count.

Create-copy should add an independent image node to the right of the group, select it, and leave the original image group unchanged.
- Canvas Agent startup, MCP status, model and permission controls, approvals, version reporting, diagnostics, streaming responses, history consistency, multi-tab isolation, and local Skill management.

- Agent message layout, Markdown, code blocks, attachments, token statistics, progress timelines, command groups, and scroll-follow behavior.
- Agent inline references: type `/` to select an enabled Skill or `@` to select a canvas asset at the caret; tokens should remain aligned with text, support keyboard navigation and hover previews, and preserve their positions after sending or refreshing.
- Agent message metadata: image attachments, Skills, canvas references, and local previews should survive page refreshes and Agent restarts through exact `clientMessageId`, `threadId`, and `turnId` ownership; protocol upgrades must not reset the independent storage format, unknown or damaged storage must refuse writes without overwriting files, no records may be silently pruned by count or size, and deleting a thread should remove its metadata and preview assets without relying on browser IndexedDB or text matching.
- Prompt Center layout, source synchronization, search, asset insertion, prompt detail dialogs, and compact split-layout prompt pickers in the image and video workbenches.
- Workbench history image cleanup: after generating content in the image or video workbench, deleting an asset, canvas image node, canvas content, or canvas project must not remove thumbnails, results, or references from generation history; deleting a generation record should still remove its dedicated local files.
- Settings import/export and WebDAV configuration: exports must omit website Key sources and credentials while retaining user preferences, prompt sources, and WebDAV settings; importing must preserve the currently synchronized website Keys and repair invalid default model references against those sources.
- Local storage settings: the Settings page should provide a Local storage tab that reads only the `infinite-canvas` database and shows IndexedDB usage, total site usage, browser quota, quota percentage, and per-object-store record counts and content size; refreshing after local data changes should update the figures without blocking the rest of the page.
