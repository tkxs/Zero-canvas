# Quick Start

To try the project, deploy or start the `web/` frontend. All business pages require USA0 OAuth; only the home page and OAuth callback remain public.

## Deploy with Vercel

Import the repository into Vercel. The root `vercel.json` builds `web/`, and the official service origin defaults to `https://usa0.top`. Before using OAuth in production, use a stable HTTPS canvas origin and have the external official service register that origin for CORS and its exact `<origin>/oauth/callback` redirect URI. Wildcards and changing preview domains are not supported.

## Run locally

```bash
git clone git@github.com:tkxs/Zero-canvas.git
cd Zero-canvas/web
bun install
bun run dev
```

Open `http://localhost:3000`.

## Run with Docker

```bash
docker build -t infinite-canvas .
docker run --rm -p 3000:3000 infinite-canvas
```

## First-time setup

- Sign in with USA0. An existing website login cookie is reused only by the official same-origin `/oauth/authorize` page; the canvas never reads or transmits the website cookie or website token.
- After authorization, the canvas automatically synchronizes all official Keys. Each Key is an independent model source, and duplicate model names remain distinguishable by Key.
- If the account has no Key, open Account Management, select an official website group, and create one. Creating or deleting a Key updates the official website, which remains the source of truth.
- Open `/prompts` to fetch prompt repositories directly from the browser and cache them in IndexedDB.
- Configure WebDAV if you want to synchronize canvases, assets, and generation history across devices.

There are no custom or local channels and no manual `Base URL`, API Key, or model setup. Full official Keys are kept only in runtime memory. Canvas projects and My Assets remain primarily stored in the browser.
