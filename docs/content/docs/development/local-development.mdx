# Local Development

The main application lives in `web/`. Business pages use USA0 OAuth and official Keys; there are no custom or local channels or manual endpoint credentials.

## Start the frontend

```bash
cd web
bun install
bun run dev
```

Open `http://localhost:3000`. Source development and `docker-compose.local.yml` connect to the local test service at `http://localhost:8080` by default. Authorization uses `http://localhost:8080/oauth/authorize`, and model synchronization uses `http://localhost:8080/v1/models`. Override the source-development origin with `VITE_USA0_ORIGIN` or the container origin with `USA0_ORIGIN`; production builds still default to `https://usa0.top`. Loopback HTTP is allowed for local development, while non-loopback deployments must use HTTPS.

Sign in before opening a business page. The test service's same-origin `/oauth/authorize` page may naturally reuse its login cookie, but canvas requests do not include that cookie and the canvas never reads or forwards a website token. After authorization, all service Keys and their models synchronize automatically. Each Key remains an independent source, including when model names are duplicated. Full Key values exist only in runtime memory; create and delete operations update the service as the source of truth.

For a non-loopback development origin, the external official service must register both the exact `<origin>/oauth/callback` redirect URI and the exact CORS origin.

Prompt sources and WebDAV are also accessed directly by the browser.

## Start the documentation site

```bash
cd docs
bun run dev
```

Common locations:

- Canvas, pages, and interactions: `web/`
- USA0 OAuth and Key APIs: `web/src/services/api/usa0-auth.ts`
- Runtime-only Key storage: `web/src/services/api/usa0-runtime.ts`
- Prompt caching: `web/src/services/api/prompts.ts`
- Documentation content: `docs/content/docs/`
