# 漏洞提交

安全策略英文原文见 [SECURITY.md](https://github.com/tkxs/Zero-canvas/blob/main/SECURITY.md)。

请不要在公开 Issue 中直接发布漏洞细节、可利用代码、私密 API Key、截图中的敏感信息或真实用户数据。

## 提交流程

优先使用当前 GitHub 仓库的私密漏洞报告或 Security Advisory。

如果暂时无法使用私密渠道，可以先开一个公开 Issue 请求维护者提供私密联系方式，但不要在 Issue 中写入漏洞细节。

## 建议提供的信息

- 受影响的版本、提交、分支或部署方式。
- 清晰的复现步骤。
- 漏洞影响、攻击场景和触发条件。
- 已脱敏的日志、截图或 PoC。
- 是否涉及 OAuth、官网完整 Key、浏览器本地存储、WebDAV、节点插件或接口请求。

## 凭证边界

业务页面使用 USA0 OAuth Authorization Code + S256 PKCE 门禁。OAuth 回调只携带 `code`、`state` 或 `error`；官网登录 Cookie 只用于同源授权页，画布不得读取或传输。

官网完整 Key 只存在于运行时内存，不得进入持久化配置、配置导入导出、WebDAV、日志、错误信息、DOM、URL、`postMessage`、`BroadcastChannel` 或插件 SDK。每个 Key 是独立模型来源；节点和任务保存精确的 `usa0-key-<Key ID>::<模型名>`，原来源失效时必须失败，不能回退到其他 Key。

## 范围说明

节点插件在页面上下文中执行，因此只能安装可信来源；插件 SDK 仅取得不透明模型来源值和宿主代执行的生成能力，不会取得官网完整 Key。绕过插件安装确认、突破上述凭证边界，或由仓库代码导致的 XSS、敏感信息泄露、文件处理、导入导出、WebDAV、权限控制和供应链问题属于重点处理范围。

第三方模型服务、托管平台、浏览器扩展、用户在项目外自行泄露的凭据、没有实际利用路径的安全头建议、纯社工钓鱼或账号找回问题通常不属于本项目漏洞范围。
