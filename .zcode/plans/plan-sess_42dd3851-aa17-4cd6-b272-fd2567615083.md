## 登录认证弹窗样式优化方案

### 设计方向

采用与当前画布一致的“克制、轻量、工作台式”视觉：中性配色、清晰分区、扁平操作，不加入渐变、装饰图形或嵌套卡片。继续使用 Ant Design 主题 token、现有语义颜色和 Lucide 图标，完整支持浅色/深色与中英文。

### 1. 重构弹窗视觉层级

修改 `web/src/components/layout/usa0-account-modal.tsx`，只调整展示结构，不改变认证和 Key 管理动作：

- 保持全局单一 Modal、居中、无默认 footer，宽度控制在约 `680–720px`。
- 使用自定义标题区表达“USA零账号”和当前状态，减少默认标题与正文重复。
- 给正文设置稳定的 `max-height` 和内部滚动，避免 Key 较多时整个弹窗超出视口。
- 使用 `antdTheme.useToken()` 与 `border-border`、`text-muted-foreground` 等现有语义样式，收敛当前分散的 `stone` 明暗颜色分支。
- 保持区块为无框分区和细分隔线；仅 Key 列表项作为重复条目使用单层轻量容器。

### 2. 优化未登录和认证中状态

- 未登录首屏突出账号身份说明和唯一主操作“登录或注册并授权”。
- 明确提示授权在 USA零官网窗口完成，不做站内账号密码表单。
- 将 `restoring`、`authorizing`、`syncing` 的视觉状态区分开：恢复会话、等待官网授权、同步账号数据分别展示准确文案和加载反馈。
- 错误继续使用就近的 `Alert`，官网链接保留为低权重次级操作。
- 不展示 OAuth code、token、完整 Key 或任何敏感信息。

### 3. 优化已登录账号与 Key 管理

- 顶部账号区展示头像、用户名/邮箱和连接状态，增加简洁的 Key 数量与已同步模型数量摘要，数据均由现有 store 派生，不新增状态。
- Key 区标题、说明和同步操作重新排版，使同步按钮保持次级权重。
- 分组选择与创建按钮改为稳定响应式布局：桌面同排，窄屏纵向排列且按钮占满可用宽度。
- Key 行强化名称、分组、可用状态和模型数量的扫描层级；错误和用量信息仍显示在所属 Key 下方。
- “查看用量”和删除操作在桌面保持紧凑，在窄屏移到独立操作行，避免长名称、Tag 与按钮互相挤压。
- 无 Key、无分组、同步失败、不可用 Key 等现有状态全部保留；创建仍要求用户明确选择分组并点击确认。
- 退出登录、打开官网放在底部轻量操作区，删除继续使用现有危险确认框。

### 4. 响应式与可访问性

- 使用 `dvh` 限制弹窗内容高度，Key 列表使用现有细滚动条样式。
- 确保英文长文案、长 Key 名称和分组名不会撑破布局；必要处使用 `min-w-0`、换行或截断并保留 title。
- 图标按钮继续提供 `aria-label`；主操作保留明确文字和 loading/disabled 状态。
- 保持现有键盘关闭、Modal 焦点管理和 Ant Design 交互语义。

### 5. 文案与文档同步

- 更新 `web/src/i18n/locales/zh-CN.ts` 与 `en-US.ts`，补充认证中状态、账号摘要等新增界面文案，保持中英文结构一致。
- 在 `CHANGELOG.md` 的 `Unreleased` 增加一条 `[优化]`，归纳登录认证与账号 Key 管理弹窗的视觉和移动端体验改进。
- 在中英文 `pending-test.mdx` 中补充本次可测试变化；检查 `todo.mdx`，没有对应待办则不改。

### 6. 保持不变的行为边界

- 不修改 OAuth Authorization Code + S256 PKCE、state 校验、回调页、token 生命周期或跨标签同步。
- 不修改 `ready/needs-key` 判定、路由门禁、待访问路径恢复和自动开窗规则。
- 不修改 Key 同步、创建、删除、用量查询或精确 `sourceKeyId` 模型路由。
- 不让完整 Key 或 OAuth token 进入 DOM、日志、URL、持久化配置或消息通道。
- 按项目约束不执行构建、测试或类型检查；完成后检查实际 diff。若已有本地页面可访问，再使用独立浏览器标签对桌面/移动端、浅色/深色和中英文做只读视觉验收，不关闭用户现有标签页。
