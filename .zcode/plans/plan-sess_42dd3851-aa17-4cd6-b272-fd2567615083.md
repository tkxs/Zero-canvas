## 首次 OAuth 登录弹窗修复方案

### 1. 保证第一次点击同步打开授权窗口

修改 `web/src/services/api/usa0-auth.ts`：

- 提取同步的 `openUsa0AuthPopup()`，负责校验当前回调地址、调用 `window.open("about:blank", ...)` 并立即显示“正在连接”占位内容。
- 浏览器拦截弹窗时继续返回现有明确错误；占位内容初始化失败时立即关闭窗口。
- 将 `authorizeUsa0WithPopup()` 改为接收已经打开的 `Window`，内部只处理 installation ID、PKCE、授权请求、回调和 code 换 token，不再自行延迟开窗。
- 所有授权准备、网络请求或 code 交换失败路径统一关闭占位窗口，并继续通过现有脱敏错误处理，避免 verifier、code 或 token 泄露。

修改 `web/src/stores/use-usa0-auth-store.ts`：

- 在 `login()` 的第一个 `await` 之前同步调用 `openUsa0AuthPopup()`，再读取 localforage 中的 baseline session。
- 把 baseline 读取放入现有错误处理范围，并将 popup 传给 `authorizeUsa0WithPopup()`。
- 保持现有 `sessionEpoch`、`authorizingSessionId`、`acceptToken()` 和跨标签会话判断顺序，不改变账号切换或历史会话隔离。
- 失败时兜底关闭窗口并恢复原有状态，防止首次本地存储读取失败留下空白页。

### 2. 避免正常回调被误判为“窗口已关闭”

调整 `waitForOAuthCallback()`：

- 浏览器支持现有按 state 隔离的 `BroadcastChannel` 时，不再读取 `popup.closed`；这样官网页面的 COOP 隔离或 callback 正常关闭窗口不会提前销毁回调通道。
- 保留严格的 callback 类型/state 校验、同源 `postMessage` 校验和五分钟授权超时。
- 仅在不支持 BroadcastChannel 的兼容路径保留窗口关闭检测，并增加短暂消息投递宽限期，避免 callback 先关闭、postMessage 后到达时误报。
- 成功、错误和超时都继续统一清理监听器、定时器、频道和窗口。

`web/src/pages/oauth/callback.tsx` 的 payload 校验、URL 清理和不传递 token/Key 的边界保持不变，不引入新的跨窗口协议。
